# V6 网站视觉重构设计

## 目标

把当前网站从“深色后台面板”重构为一座适合长期阅读的个人知识库。V6 只调整视觉系统、版式与交互反馈，不改变论文、里程碑模型、文章和搜索的数据契约；“跑得还快”继续保留占位页，不接入地图。

用户进入任一页面后，应在三秒内分清三件事：当前属于哪个知识主题、这一页有哪些内容、正文从哪里开始。

## 当前问题

- 一级与二级侧栏合计占据约 400px，主题切换和目录树权重接近，正文被挤压。
- 一级侧栏使用大面积黑色块，激活项又切回正文底色，视觉断裂且像后台导航。
- 二级侧栏虽已移除主题说明，但 `CONTENTS / 目录` 工具栏和树形列表仍显得机械、拥挤。
- 首页超大标题、统计、主题标题与密集表格同时强调，字号层级没有稳定节奏。
- 文章为空时，页面只剩大标题和大片空白，没有形成可阅读的版心。
- 移动端论文表格可用，但月份横向滚动、顶部三个浮动按钮和正文首屏仍互相争夺空间。

## 设计方向：极简知识罗盘

### 主题与受众

这是高级算法工程师维护的个人知识库。它不是资讯门户，也不是管理后台；页面的单一任务是让维护者和读者快速定位一条知识路径并进入阅读。

### 视觉令牌

- `Porcelain #F7F8FA`：冷白画布，避免常见的奶油纸张模板感。
- `Paper #FFFFFF`：正文与浮层。
- `Graphite #17202B`：正文墨色。
- `Slate #667180`：说明与元数据。
- `Hairline #DDE2E8`：结构分隔。
- `Bearing Blue #3157D5`：唯一强调色，表示当前方位与可操作状态。
- 深色模式使用 `Night #0D121A`、`Night Paper #121A24`、`Mist #E9EEF5`，保留同一蓝色方位语义。

字体分工：

- 展示与界面：`Inter Tight` 风格的本地系统窄体栈，中文回退至 `PingFang SC / Microsoft YaHei`；标题重心靠字宽、留白和字重建立，不依赖装饰字体。
- 长文正文：`Source Han Serif / Noto Serif SC / Songti SC`，维持技术文章的阅读节奏。
- 数据与元信息：`IBM Plex Mono` 风格的等宽系统栈，只用于日期、数量、arXiv ID 和快捷键。

不引入远程字体。原因是这是可离线、自托管的知识库；用户影响是首次加载稳定，不受字体 CDN 和网络环境影响。

### 布局

桌面端：

```text
┌──────────┬────────────────────┬──────────────────────────────────────┐
│ TO/GOS   │ 本页目录        ‹  │ 搜索                         主题切换 │
│    ○     ├────────────────────┤                                      │
│    ● 学习│ 主题 / 年 / 月     │ 主题名                                │
│    ○ 模型│                    │ 主题说明                              │
│    ○ 文章│                    │ ──────────────────────────────────── │
│    ○ 城市│                    │ 正文                                 │
└──────────┴────────────────────┴──────────────────────────────────────┘
```

- 一级侧栏固定为 7rem 左右，成为紧凑的“方位轨道”。四个主题由同一条竖线串联，圆点表示方向，激活项用实心蓝点与高对比文字表达。
- 二级侧栏约 16rem，只有“本页目录”、折叠按钮和导航内容，不出现主题名或主题说明。
- 主内容建立最大版心；搜索与主题按钮组成轻量顶部工具区，不再漂成三个无关方框。
- 二级侧栏折叠后保留窄把手，正文平滑扩展。

移动端：

```text
┌──────────────────────────┐
│ 导航      搜索       主题 │
├──────────────────────────┤
│ 主题名                    │
│ 主题说明                  │
│ 页面标题                  │
├──────────────────────────┤
│ 正文                      │
└──────────────────────────┘
```

- 一级与二级导航合并进入抽屉，但继续用色块和标题区分职责。
- 顶部控制收进同一工具栏，触控目标至少 44px。
- 论文卡片保持字段标签，月份导航改为可感知的横向滚动区，不让滚动条成为主要视觉元素。

### 字体层级

- 主题眉题：`0.75rem / 700`，用于“学习一个”等当前方位。
- 主题说明：`0.95–1.05rem / 400`，比正文稍弱。
- 页面主标题：`clamp(2.6rem, 6vw, 5.25rem)`，首页只出现一次。
- 内容分区标题：`clamp(1.65rem, 3vw, 2.35rem)`。
- 条目标题：`0.94–1.08rem / 650`。
- 正文：`1rem / 1.7`；长文正文在宽屏为 `1.0625rem / 1.82`。
- 元数据：`0.6875–0.75rem`，等宽字体且不承担核心信息。

### 记忆点

唯一的视觉签名是一级侧栏的“方位轨道”：品牌下方一条细线串联四个主题节点，激活节点展开为短横向方位标记。它把“知识罗盘”变成真实的信息结构，而不是额外图案。

### 动效

- 仅保留侧栏折叠、抽屉出现和交互焦点的 160–220ms 过渡。
- 不做滚动入场、背景粒子或装饰动画；它们会干扰论文表格与长文阅读。
- `prefers-reduced-motion` 下关闭所有位移过渡。

## 页面处理

### 学习一个

- 首屏将主题名、说明、页面标题和统计组织成单一标题区。
- 论文主题分区用明确的标题、数量和细分线建立节奏。
- 表格提高标题与作者可读性，arXiv ID、状态退为元数据。

### 身经百战

- 延续同一标题区与版心。
- 时间线作为页面主交互，不使用额外卡片装饰；比较表格强化冻结表头和版本列。

### 谈笑风生

- 空状态也维持完整标题区，并给出明确说明，不用大块无意义留白制造“极简”。
- 有内容后，列表表现为编辑式文章流：日期为辅助轴，标题与摘要为阅读入口。
- 文章页收窄正文行长，目录保持安静，代码与表格只在需要时横向滚动。

### 跑得还快

- V6 仅应用统一壳层和空状态；不新增地图服务、城市数据或图片上传能力。

## 无障碍与兼容性

- 所有按钮保留可见焦点、可读标签和 44px 触控面积。
- 激活状态同时使用位置、形状和文字权重，不只依赖颜色。
- 浅色与深色主题均保持正文和辅助文字的可辨识对比度。
- 支持 390px 移动端、900px 抽屉断点和 1440px 桌面端。
- 保留无 JavaScript 时可访问的导航与正文。

## 自我审查

初始方案曾考虑“暖白纸张 + 衬线大标题 + 砖红色强调”，但这与常见 AI 编辑部模板过于接近，也不能体现算法工程师知识库的技术属性，因此改为冷白、石墨与方位蓝，并以真实导航节点作为签名。最终方案的大胆之处只放在一级侧栏轨道上，其余区域以排版和间距取胜。

## 验收标准

- 二级侧栏中不出现四个主题名及其说明；主题名和说明只在正文顶部出现。
- 桌面端一级侧栏明显变窄，折叠二级侧栏后正文宽度同步增加。
- 四类页面使用一致的颜色、字体层级、工具栏和焦点反馈。
- 搜索、深浅主题、二级侧栏折叠、移动端抽屉和现有深链行为不回归。
- 390×844 与 1440×1000 下无页面级横向溢出；论文与比较表格只在自身容器内滚动。
- 通过 Python 语法、JavaScript 语法、站点构建、HTML 结构断言与 `git diff --check`。
