# LOKEN V9 新版论文摘要自动化设计

## 目标

把工作日 arXiv 筛选任务接入 V7 已实现的 `papers.summaries` 流水线。筛选、摘要、构建和推送仍是两个独立提交；任意单篇论文失败只记录该论文并继续，其他成功摘要必须能够验证、提交和推送。

## 边界

- 公共仓库继续只包含通用 Python 摘要模块与公开生成结果。
- WSL service 名、模型地址、虚拟环境、私有笔记根和 Git 传输配置只存在于本机忽略的 `ops/`。
- 定时任务不再调用旧摘要实现；筛选阶段暂时仍使用现有本地 `daily_arxiv.py --apply-curation`，摘要阶段唯一入口是 `python -m papers.summaries run`。
- V9 不修改网站视觉、地图、Notion/微信读书能力或 README。

## 工作日流程

1. Windows 自动任务确认 main 与工作区洁净并 `pull --ff-only`。
2. 收集并审核所有 pending 候选，先提交推送筛选结果。
3. 仓库重新洁净后，在 WSL 调用私有 `ops/summary_runtime.sh weekday`。
4. 运行脚本加独占锁、同步依赖、启动端侧模型，并从 loopback `/v1/models` 解析实际模型 ID。
5. 调用 `python -m papers.summaries run --limit 100`。退出码 `0` 为全部成功，`3` 为单篇部分失败；两者都继续验证和发布，其他退出码停止。
6. V7 工作流逐篇执行 HTML-first 获取。只有 `404/410/415`、非 HTML 或有效正文不足才允许 PDF fallback；超时、DNS、TLS、`429`、`5xx` 在有限重试后只失败当前论文，绝不偷偷降级 PDF。
7. 工作流先安全发布成功论文并重建站点；脚本随后验证隐私、语法和差异，只暂存公开摘要及实际生成页面。无变化不提交。
8. 无论成功、部分失败还是异常，清理 trap 都停止本轮启动的 vLLM。自动任务从私有 `build/paper-summaries/report.json` 汇报每篇状态。

## 失败语义

- 单篇获取、解析、推理或结构化输出失败：记录安全错误，继续下一篇；成功项仍可发布。
- 账本、私有状态、历史页面、公共事务或回滚不安全：整批停止，不提交。
- 推送拒绝：停止，不强推。
- 已有摘要默认幂等跳过；只有显式单篇 refresh 才覆盖。

## 验收

- 本地脚本只接受 `weekday`/`weekend`，且 `bash -n` 通过。
- mock/静态契约证明 CLI 退出 `3` 后仍进入发布检查，退出 `2` 不发布。
- 自动任务提示明确 HTML-first 的暂时失败语义、逐篇失败列表、私有报告和 GPU 停止状态。
- 公共仓库与生成页不包含本地路径、service 名、模型原始响应或缓存。
